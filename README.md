# Vozduhan.AI

Бот группы ИКБО-66-25: болтовня в «Воздуханстве», расписание с чётными/нечётными неделями и разовыми изменениями, дедлайны, личка-ассистент, редактирование через Telegram и веб-админку, журнал всех сообщений. .NET 10, SQLite, OpenRouter (GLM-5.3 Flash), Telegram Bot API через HTTP. Очереди на сдачу пока не реализованы.

## Что умеет

**Чат.** В Воздуханстве отвечает по @упоминанию и на ответы ему, в личке — на всё. Отвечает «как человек»: иногда сразу ставит 👀/👍/👌 (а иногда ничего), показывает «печатает…», делит ответ на 1–3 сообщения с паузами по длине текста. Форматирует HTML Telegram: жирный, курсив, подчёркнутый, зачёркнутый, спойлер, моноширинный, цитаты (в том числе сворачиваемые), ссылки, даты `tg-time` в часовом поясе читателя. Разметка проходит через фильтр разрешённых тегов; если Telegram её всё равно отвергнет, ответ уйдёт обычным текстом. Посты дедлайнов, карточки и команды не делятся и не форматируются.

**Расписание.** Знает текущую и следующую пару, ближайшие дни с отменами и переносами, кто ведёт лекции и практики, кабинеты, корпуса (Вернадка / Малая Пироговская), звонки, сленг предметов. Команды без нейронки: `/today`, `/tomorrow`, `/week [next]`, `/date 31.10`, `/next`, `/subjects`, `/roster`, `/deadlines` (в группе — с @упоминанием бота).

**Редактирование в личке (разработчик и староста).** Пиши обычным текстом — бот сам решает, болтовня это, дедлайн или изменение реестра, и перед сохранением показывает карточку с кнопкой «Применить». Можно поправить уточнением — карточка пересоберётся. Примеры:

> 31-го в субботу матан лекция 6-й парой дистанционно
> Иванова отчислили
> с 9 ноября джава по пятницам в В-404
> в понедельник физры не будет

`/undo` откатывает последнее изменение реестра. `/web` даёт одноразовую ссылку в веб-админку. Второй редактор получает уведомление о каждом изменении. Старые команды дедлайнов (`/deadline`, `/edit`, `/move`, `/cancel`, `/discard`) работают как раньше.

**Веб-админка** (через VPN, по IP): неделя с разовыми изменениями в пару кликов, постоянное расписание, разовые изменения, дедлайны (создание, перенос, отмена с публикацией), предметы, список группы, звонки и семестр, журнал сообщений, запросы к ИИ (промпт, данные, ответ), люди в Telegram с привязкой ID, история версий с откатом, экспорт реестра.

**Темы группы.** «Воздуханство» — болтовня, ответы на упоминания и случайные вбросы. «Дедлайны» — карточки сдач (закреп ближайших) и новости об изменениях с живой вводкой от ИИ («!!! Арапов перенёс сдачу по философии на пятницу») и точными фактами ниже. «Сводка» (`summaryTopicId`) — всё, что бот пишет сам: утро, напоминания, будильники к дедлайнам, посты по `/post`.

**Инициатива бота** (блок `ambient`):
- 08:00 — утреннее сообщение в «Сводку»: живое вступление от ИИ (каждый день новое, может дёрнуть кого-то с тегом) + расписание дня + сдачи на ближайшие три дня. `morningTime` — необязательный дополнительный утренний вброс в Воздуханство (по умолчанию выключен).
- До `spontaneousPerDay` случайных вбросов днём в Воздуханство (10:00–21:30), только если есть повод; иначе бот молчит.
- 20:00 — напоминание в «Сводку» о завтрашних сдачах.
- Будильники к дедлайнам: для каждого дедлайна ИИ сам выбирает 1–5 моментов (за неделю, за 3 дня, накануне, перед парой) и пишет в «Сводку» прожарку-напоминание. Перенос дедлайна перепланирует их, отмена убирает.
- Всё видно и правится в админке → «План бота»: дни, вбросы, будильники (удалить, добавить, перепланировать ИИ), отложенные посты.
- `/post [идея]` в личке (только разработчик) или «напиши группе про сходку в 15:00» — черновик с кнопками «В Сводку / В Воздуханство / Ещё вариант / Не надо». То же в админке, плюс «Запланировать» на время (уходит в Сводку).
- Когда бот обращается к человеку, он тегает его @юзернеймом (или кликабельным упоминанием, если юзернейма нет).
- Прогрев (только разработчик): у каждого запланированного сообщения в «Плане бота» есть 🔥 (сгенерировать заранее и посмотреть точный вид), ✏️ (поправить или написать вручную; `SKIP` — промолчать), ↺ (сбросить — бот напишет в момент отправки), 🚫 / ↩ (отменить / вернуть). Прогретый текст уходит как есть; расписание и сдачи в сводке подставляются свежими.
- Настройки инициативы (вкл/выкл, время утра и вечера, число и окно вбросов) меняются в «Плане бота» → «Настройки инициативы», хранятся в базе и действуют сразу; «Сбросить к конфигу» возвращает блок `ambient` из файла.
- Опоздавшие больше чем на 2 часа события (бот лежал) пропускаются, чтобы не заспамить чат.

**Выбор модели.** `modelRouting` отправляет задачи с планированием на полную `z-ai/glm-5.3`: разбор сообщений редактора (`plan`), разбор дедлайнов (`deadline`), план будильников (`wakeplan`). Всё остальное — болтовня, посты, вводки — идёт на `model` (Flash), это дешевле. Если полная модель недоступна, запрос автоматически повторяется на Flash. Какая модель ответила, видно во вкладке «ИИ-запросы».

**Адаптивное мышление.** `reasoningEffort` задаёт глубину рассуждений по задачам: ответы в чат — `low` (быстро), разбор команд редактора, планирование будильников и посты — `medium`. Если ответ упёрся в лимит (`finish_reason=length`, пустой текст или оборванный JSON), он перегенерируется с удвоенным `maxOutputTokens`, до `maxOutputTokensCeiling` (16384). Сколько было попыток и с каким бюджетом, видно во вкладке «ИИ-запросы».

**Посты в «Дедлайнах»** устроены как утренняя сводка: сверху живой текст бота в его характере (новая сдача, перенос, отмена — каждый раз по-своему), снизу карточка, которую собирает программа: предмет и работа, день, пара, время, кабинет, препод, корпус. Комментарий редактора («последний шанс», «Арапов перенёс») — закулисный: бот использует его для текста, но дословно не печатает. Перед сохранением в личке видно, как будет выглядеть пост. В админке у дедлайна есть «✨ Текст» — переписать живой текст, карточка обновится без нового уведомления. Если карточку удалили, а потом сдачу отменили, бот не воскрешает её, а присылает одну новость об отмене.

**Дедлайн с ИИ.** В личке просто: «матан контроша в пятницу», «сиаод 2-я практика 31-го». Предмет — по сленгу, дата — от сегодняшней, пара, время и кабинет — из расписания. Если чего-то не хватает (нет пары в этот день, неясно какую практику), бот переспросит; ответь уточнением — карточка пересоберётся. «Контрольная работа» без номера — нормально; практика и лаба — с номером.

**Журнал.** Каждое входящее и исходящее сообщение (личка, Воздуханство, темы, удаления модерации, правки постов) и каждый запрос к ИИ сохраняются в SQLite. Сроки: `logDays` (365) и `aiLogDays` (30).

## Кто что видит

| | Разработчик (`ownerId`) | Староста (`role: head`) |
|---|---|---|
| Расписание, разовые изменения, звонки, семестр | ✅ | ✅ |
| Дедлайны | ✅ | ✅ |
| Список группы, Telegram ID | ✅ | ✅ |
| Назначить/снять старосту | ✅ | ❌ |
| Сленг предметов, комментарии к предметам, заметки о людях, текст знаний | ✅ | ❌ не видит и не меняет |
| ИИ-запросы (там системный промпт) | ✅ | ❌ |
| Журнал своей лички с ботом | ✅ | ❌ личка разработчика скрыта |

Владельца меняет только серверный конфиг. Скрытые поля вырезаются из API, экспорта, уведомлений, истории, промпта планировщика старосты и даже из кода страницы, которую получает староста. При сохранении из админки старостой скрытые поля всегда берутся из текущей версии.

**Знания** (`knowledge`) и **комментарии к предметам** идут в системный промпт любого чата. **Заметки о людях** (`adminNote`) — только в Воздуханстве, для редких дружеских прожарок; в личке не используются.

## Где живут данные

`config/bot.local.json` → `/etc/vozduhan-ai.json` — это **начальное** значение реестра (участники, предметы, пары, звонки, разовые изменения, знания). При первом запуске он импортируется в базу. Дальше главная — база: правки из Telegram и админки сохраняются версиями и переживают перезапуски и деплои.

Чтобы конфиг снова заменил базу (например, после ручного редактирования JSON), подними `registryVersion` на 1 и задеплой. Импорт тоже станет версией в истории, его можно откатить. Скачать текущее состояние в формате конфига: админка → «Звонки и семестр» → «Скачать JSON».

Формат пар: `dayOfWeek` 1–7 (пн–вс), `weeks` `all`/`odd`/`even`, `kind` `lecture`/`practice`/`lab`, `room`, `teacher`, `campus` (пусто — `defaultCampus`), `online`, `note`, `from`/`until`. Разовые изменения `scheduleChanges`: `type` `add` (доп. пара), `cancel` (`lessonId` или `subjectId` [+`period`]), `modify` (`lessonId` + новые значения), `dayoff`.

`weekOneMonday` — понедельник первой (нечётной) недели. Сейчас `2026-08-31`, то есть 1 сентября — первая неделя, а 19–25 октября — 8-я, чётная. Если не так, поменяй в админке → «Звонки и семестр»: там сразу видно, какая неделя сегодня.

## Деплой

Как раньше: `deploy.bat`. Он собирает, проверяет `config/bot.local.json`, копирует на `dolbilkus`, ставит конфиг и перезапускает сервис. Новая схема БД (версия 2) создаётся сама, старые дедлайны и история остаются.

Веб-админка слушает `web.listen` (`http://*:8080/`) и пускает только из `web.allowedNetworks` (`10.8.0.0/24` — VPN, плюс localhost). Адрес для ссылок — `web.publicUrl` (`http://10.8.0.23:8080`).

- Если на мини-ПК включён `ufw`: `sudo ufw allow in on dolbilkus-awg to any port 8080 proto tcp`.
- Проверка с ноутбука в VPN: открыть `http://10.8.0.23:8080` — должна быть страница входа. Если не открывается, VPN-сервер, возможно, не пропускает трафик между клиентами (client isolation); тогда это настройка VPN-сервера.
- Telegram недоступен, а войти надо — ссылка прямо с сервера:

```bash
BOT_CONFIG_PATH=/etc/vozduhan-ai.json BOT_DATA_PATH=/var/lib/vozduhan-ai/vozduhan.db \
  dotnet /opt/vozduhan-ai/Vozduhan.AI.dll --web-link
```

Вход — одноразовая ссылка на 10 минут, дальше cookie-сессия на `web.sessionDays` дней. POST-запросы требуют служебный заголовок (защита от CSRF). Шифрование трафика даёт VPN.

## Как получить IDs

`dotnet run -- --discover` печатает userId/chatId/topicId без текста (сервис с тем же токеном сначала остановить). Теперь удобнее админка → «Люди в Telegram»: там все, кто писал боту или в группу, с кнопкой «Привязать» к записи списка.

## Поведение при сбоях

- Полученный update сначала пишется в SQLite, повторы не удваивают работу. У каждого автора задания идут последовательно; модерация и кнопки — отдельными исполнителями.
- Готовый ответ ИИ сохраняется до отправки: при сбое Telegram он не генерируется заново, уже отправленные части не дублируются.
- Изменение реестра атомарно: проверка целостности, проверка прав старосты, новая версия, мгновенная подмена в памяти. Две одновременные правки из админки: вторая получает «реестр уже изменили».
- Отчисленный становится неактивным: доступ пропадает сразу, история и дедлайны остаются.
- Ошибка ИИ в планировщике ничего не меняет; команды и админка работают без OpenRouter.
- Ежедневные локальные SQLite-бэкапы, последние семь.

## Проверки

```text
dotnet build -c Release
dotnet run --project tests/Vozduhan.AI.Tests.csproj -c Release
```

Тесты используют временную SQLite, подставные Telegram/OpenRouter и настоящий локальный HTTP-сервер админки. Если рядом лежит `config/bot.local.json`, проверяется и реальное расписание (чётность, корпуса, лекции/практики, разовая дистанционная лекция 31.10).
