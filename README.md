# Vozduhan.AI

Первый рабочий срез: закрытые дедлайны и диалог в «Воздуханстве». .NET 10, SQLite, OpenRouter GLM-5.3 Flash, Telegram Bot API через HTTP. Токены остаются в переменных окружения. Очереди, личные напоминания, веб-поиск и отдельная сводка не реализованы.

## Что работает

- Один разрешённый chat ID; всё вне него игнорируется. Личка — только для активных участников списка и разработчика. Неизвестному пользователю не отвечает даже `/start`.
- Редактирование дедлайнов только в личке: владелец по `ownerId` и один участник с ролью `head`. Обычные участники не могут изменять данные ни фразой, ни командой, ни чужой кнопкой.
- Ввод естественной фразой → уточнение недостающих полей → карточка → подтверждение. Имя предмета сопоставляется с реестром; кабинет берётся только из него. Время — из расписания звонков и пары.
- Одна карточка на каждую сдачу. По умолчанию закреплены максимум три ближайшие в пределах трёх календарных дней. Прошедшие/отменённые карточки открепляются. Чужие закрепы не трогаются.
- Один утренний пост на день со всеми сдачами. Его полный текст хранится в БД заранее. Изменения корректируют существующий пост, а не размножают его. Очень длинный список разбивается на части.
- Перенос/отмена обновляет исходную карточку и будущие утренние посты; отдельная неформальная новость появляется в теме дедлайнов. До отдельной реализации нет объявлений «через три дня» в Воздуханстве.
- Последние 30 сообщений текущего разговора, точный reply, выбранная цитата, до восьми сохранённых предков ответа. В модель отдельно передаётся фокусное сообщение. Истории других тем/личек не подмешиваются.
- Из списка группы передаются username, краткое имя и ФИО. Номер по списку не используется как место в очереди. Самой очереди пока нет.
- В групповой болтовне отвечает только по настоящему Telegram-упоминанию или reply к боту. Реакция 👀 с попыткой 👍 при ошибке, загрузка, финальный ответ и удаление загрузки.
- В AI-темах, указанных IDs, пользовательский контент удаляется. Модерация не ждёт завершения генерации.
- SQLite сохраняет дедлайны, черновики, версии, готовые публикации, IDs сообщений, контекст и входящие задания. Успешно обработанные входящие payload очищаются, ID остаётся для защиты от повторов.
- Согласованные локальные SQLite-backups ежедневно, последние семь. Отдельную копию вне сервера стоит организовать отдельно.

## Сначала настрой тестовую копию

В примере все участники, звонки, даты расписания и кабинеты — демонстрационные. Даже А412 взят из примера разговора, это не проверенное расписание группы. Замени их реальными данными. Нулевые верхние IDs и `REPLACE_ROOM` специально не позволяют случайно запустить шаблон.

1. Распакуй архив поверх корня исходного проекта, сохраняя пути. Старые `bin`, `obj`, `publish` в архив не входят.
2. Скопируй `config/bot.example.json` в `config/bot.local.json`.
3. Заполни `ownerId`, отрицательный `groupId` именно тестовой группы, `chatTopicId` и `deadlinesTopicId`. БД привязана к этой тройке chat/topic IDs. Для другой группы нужна отдельная БД.
4. В `members` запиши числовые Telegram IDs и настоящие имена всех тестовых аккаунтов. Разработчик тоже должен быть активной записью списка. У старосты `role: "head"`, у остальных `"member"`. Владелец определяется `ownerId`, а не username.
5. В `subjects` задай IDs, названия, разговорные aliases и закреплённые кабинеты.
6. В `periods` внеси реальные начало и конец каждой пары.
7. В `lessons` внеси полное недельное расписание. `dayOfWeek`: 1 — понедельник, …, 7 — воскресенье. `weeks`: `all`, `odd`, `even`. `weekOneMonday` — понедельник первой нечётной учебной недели; настрой по своему расписанию. `from`/`until` ограничивают действие строки.
8. `scheduleOverrides`: исключения на конкретную дату, например `{ "subjectId": "siaod", "date": "2026-11-30", "period": 6 }`. Если в дату есть исключения по предмету, для него они заменяют недельные строки. Все кабинеты по-прежнему берутся из предмета.
9. В тестовой группе назначь бота администратором с Delete Messages и Pin Messages. Manage Topics можно оставить для будущих функций. Темы не закрывать. Нужны существующие темы: этот срез их сам не создаёт.

Разовая проверка конфигурации в PowerShell:

```powershell
$env:BOT_CONFIG_PATH = "$PWD/config/bot.local.json"
dotnet run -- --validate-config
```

Она не обращается к Telegram/OpenRouter. Изменения реестра применяются после перезапуска; текущая конфигурация сохраняется в БД для фиксации использованного реестра. Кабинет/пара существующего дедлайна — снимок на момент подтверждения; редактирование реестра само не переносит ранее согласованные сдачи.

## Как получить IDs

Есть режим `--discover`: получает updates и печатает только userId/chatId/topicId, не текст и не ответы. Это разовый технический режим; настройки доступа основного бота в нём не используются.

При том же токене сначала останови работающий сервис, чтобы два процесса не спорили за polling:

```powershell
ssh dolbilkus "sudo systemctl stop vozduhan-ai.service"
$env:TELEGRAM_BOT_TOKEN = 'PASTE_EXISTING_TOKEN_LOCALLY'
dotnet run -- --discover
```

Напиши боту с каждого тестового аккаунта в личку, затем по сообщению в обе тестовые темы. В терминале появятся нужные IDs. Ctrl+C завершает режим. Не запускай старую версию сервиса параллельно. При отдельном тестовом токене останавливать боевой бот не нужно.

## Запуск и деплой

Локально: задай `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY`, `BOT_CONFIG_PATH` и выполни `dotnet run`. `BOT_DATA_PATH` при необходимости переопределяет путь SQLite.

На существующем сервере секреты остаются в `/etc/vozduhan-ai.env`. `deploy.bat` / `deploy.ps1`:

1. Собирает Linux-публикацию.
2. Проверяет локальный `config/bot.local.json`, если файл существует.
3. Передаёт публикацию и обновлённый unit через существующий SSH alias `dolbilkus`.
4. Если есть локальный конфиг, устанавливает его как `/etc/vozduhan-ai.json` с владельцем `davilkus` и правами 0600. Если локального нет, сохраняет существующий серверный конфиг.
5. Обновляет systemd unit, проверяет конфигурацию и только после успешной проверки перезапускает сервис.

`StateDirectory=vozduhan-ai` разрешает SQLite запись при `ProtectSystem=strict`. БД — `/var/lib/vozduhan-ai/vozduhan.db`, резервные копии — соседний `backups/`. Деплой не заменяет их. Реестр не включается в git: `config/bot.local.json` игнорируется.

Первичную установку нового сервера можно сделать `bash deploy/setup-server.sh` из каталога исходников на сервере. Для уже установленного сервера обновлённый `deploy.ps1` сам устанавливает unit. Пользователь и SSH alias сохранены из текущего проекта.

Реальную группу включай только после тестов, используя отдельную БД. Текущая поставка не содержит её ID и ничего на сервере не включает сама.

## Пользовательские сценарии

В личке разработчика/старосты:

> Привет. Будем сдавать 11-ю практику по Сиаоду 30 ноября.

Если на этот день в расписании ровно одна пара предмета, бот подставит номер пары, точное время и кабинет. Если есть две пары или нет записи расписания, спросит номер. Фраза «будем сдавать практику» без конкретной работы требует уточнения; номер не выдумывается. Подтверди карточку кнопкой. Можно продолжить диалог уточнением, пока карточка не сохранена.

> Цынгалев перенёс сдачу Джавы на понедельник.

Если есть несколько подходящих дедлайнов, укажи ID из `/deadlines`. Не стоит полагаться на угадывание модели при неоднозначности. Для точного выбора: `/edit 12 перенеси на понедельник`.

Сообщённая редактором информация о преподавателе/причине может попасть в публичное примечание. Оно отдельно видно на карточке подтверждения. Полный текст личного сообщения в публичный пост не копируется.

Команды, не требующие OpenRouter:

```text
/start
/help
/deadlines
/subjects
/deadline siaod | Практика №11 | 2026-11-30 | 6
/move 12 2026-12-02
/move 12 2026-12-02 2
/cancel 12
/discard
/where
```

Внесение/перенос/отмена через команды тоже показывают карточку и требуют подтверждения. `/where` доступна только владельцу. Для `/deadline` используй IDs из `/subjects`. `/edit ID текст` использует ИИ; остальные перечисленные команды могут работать без ключа OpenRouter. Ограничение на редактирование проверяется повторно при нажатии кнопки.

Староста и разработчик в личке находятся в режиме работы с дедлайнами. Для обычной болтовни используй Воздуханство. Зарегистрированным обычным участникам доступен личный диалог с ботом и чтение списка, но не изменение учебных данных.

В Воздуханстве:

> @vozduhanAIbot ответь Никите по этому поводу.

Бот получает контекст темы, сведения о людях и отдельно это обращение. Reply и частичная цитата передаются явно. Если сообщение за пределами сохранённой истории и Telegram не прислал его текст, бот не может самостоятельно скачать старую переписку. Фото/файлы пока обозначаются как вложение; распознавания и веб-поиска нет.

## Поведение при сбоях

- Полученный update сначала записывается в SQLite, после этого polling продолжает с нового offset. Повторы не удваивают записи.
- У каждого автора задания идут последовательно. Для модерации отдельный исполнитель; генерация ограничена двумя одновременными запросами.
- Подтверждение дедлайна атомарно сохраняет версию и готовые утренние тексты. Повторное подтверждение не создаёт новую сдачу; устаревшая правка другого редактора отклоняется.
- Публикации идут без обращения к модели. При сбое OpenRouter во время подготовки стилистического вступления используется фактический запасной текст. Данные даты/времени/кабинета всегда форматирует приложение.
- При недоступности Telegram исходящие задания остаются в БД и повторяются. Просроченные утренние посты после конца своего дня не отправляются лавиной.
- Пропажа активной карточки обнаруживается очередной проверкой редактирования, обычно не позднее пяти минут. При обычной правке пропажа обнаружится сразу. Исторические карточки не восстанавливаются без необходимости.
- Внешняя отправка Telegram не имеет абсолютной гарантии exactly-once: при обрыве после приёма сообщения сервером и до ответа возможен дубль. Известные message IDs редактируются повторно безопасно; внутренние действия защищены от дублей.
- Обычные входящие задания после пяти неудачных попыток остаются в БД с failed-состоянием и записью в журнале, чтобы не зациклить весь диалог. Это не повторяет финансовые/учебные действия.
- Потеря прав сообщает владельцу в доступную личку, не чаще раза в час. Бот не может удалить сообщение до получения события; действуют ограничения возраста/видимости Telegram.

## Проверки

```text
dotnet build -c Release
dotnet run --project tests/Vozduhan.AI.Tests.csproj -c Release
```

Проверки используют временную SQLite и подставные HTTP-ответы. Они не отправляют сообщений людям и не тратят OpenRouter: права, повторные updates/callbacks, конфликты версий, расписание и чётность недель, перенос/отмена, готовые утренние тексты, рестарт, резервная копия, изоляция диалогов, цитаты, публикации, закрепы, пустой ответ модели.

Перед использованием с группой остаётся реальная проверка Bot API и качества русского разбора на тестовых аккаунтах с вашим расписанием. Тестовых/боевых токенов в архиве нет.
